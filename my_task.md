
# Embedding и Vector Database в RAG-системе:

# # Embedding (Векторное представление текста):

Embedding — это способ преобразования текста в числовой вектор с помощью специальной модели искусственного интеллекта.

Каждый текст (слово, предложение или фрагмент документа) преобразуется в набор чисел. Например, вектор может состоять из 1024 чисел.

Главная задача Embedding — представить смысл текста в числовой форме, чтобы компьютер мог сравнивать тексты по их смыслу, а не только по одинаковым словам.

**Как это работает?**

1. Документ разделяется на небольшие части (chunks).

2. Каждая часть передаётся в Embedding-модель.

3. Модель преобразует текст в числовой вектор.

4. Полученный вектор сохраняется в векторной базе данных.

**Пример:**

«Как поступить в РУДН?»

«Какие документы нужны для поступления в университет?»

Эти предложения используют разные слова, но имеют близкий смысл. Поэтому их векторы могут находиться близко друг к другу в векторном пространстве.

**Примеры Embedding-моделей**

Существуют разные модели для преобразования текста в числовые векторы:

**1. all-MiniLM-L6-v2** — быстрая и компактная модель, которая преобразует текст в вектор из 384 чисел. Подходит преимущественно для английского языка.

**2. multilingual-e5-large** — многоязычная модель, которая создаёт векторы из 1024 чисел. Поддерживает русский и другие языки.

**3. BAAI/bge-m3** — многоязычная модель с размерностью вектора 1024. Подходит для семантического поиска и работы с длинными текстами.

**4. text-embedding-3-small** — модель OpenAI, которая по умолчанию создаёт векторы из 1536 чисел.

**5. text-embedding-3-large** — более мощная модель OpenAI, которая по умолчанию создаёт векторы из 3072 чисел.

Для нашего проекта, который работает с документами на русском языке, можно рассмотреть multilingual-e5-large или BAAI/bge-m3, поскольку эти модели поддерживают русский язык и подходят для семантического поиска.

**Роль Embedding в нашем проекте:**

Embedding позволяет системе искать информацию в документах университета по смыслу вопроса пользователя. Это особенно полезно, когда пользователь формулирует вопрос другими словами, чем в документах.

## Vector Database (Векторная база данных)

Vector Database — это база данных, предназначенная для хранения и быстрого поиска числовых векторов.

В RAG-системе она используется для хранения Embedding-векторов, созданных из фрагментов документов.

**Как это работает?**

1. Система получает векторы текстовых фрагментов.

2. Векторы сохраняются в базе данных вместе с текстом или ссылкой на него и метаданными.

3. Когда пользователь задаёт вопрос, система преобразует его в вектор с помощью Embedding-модели.

4. База данных ищет наиболее похожие векторы.

5. Найденные фрагменты текста передаются языковой модели для формирования ответа.

6. Для сравнения векторов можно использовать косинусное сходство (Cosine Similarity).

**Примеры векторных баз данных**

**1. FAISS** — библиотека для поиска похожих векторов.

**2. Chroma** — инструмент для хранения и поиска Embedding-векторов.

**3. Qdrant** — векторная база данных для семантического поиска.

**Роль Vector Database в нашем проекте**

Векторная база данных позволяет быстро находить нужную информацию среди большого количества документов университета.

Это помогает RAG-системе получать релевантные фрагменты документов и использовать их для генерации ответов на вопросы студентов.

### Как Embedding и Vector Database работают вместе?

Документы → Chunking → Embedding → Vector Database → Поиск релевантных фрагментов → LLM → Ответ пользователю

Embedding отвечает за преобразование текста в числовые векторы, а Vector Database — за хранение этих векторов и поиск похожих.

Таким образом, эти два компонента обеспечивают семантический поиск информации и являются важной частью RAG-системы.
